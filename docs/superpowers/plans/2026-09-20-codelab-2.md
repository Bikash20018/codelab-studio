# CodeLab Studio 2.0 implementation plan

Approved scope: all improvements in the preceding recommendation. Preserve existing user changes and the Tk desktop app. No rewrite or cloud dependency.

1. Recovery and safety: atomic source writes; debounced recovery snapshots of saved and unnamed tabs; restore cursor, selected tab, project and open files; retain snapshots after crashes; discard explicitly closed tabs; tolerate corrupt/missing files. Tests cover failed replacement, unsaved recovery and external changes.
2. Editor tools: clang-format-backed one-click formatting, whole-operation undo, loop/function/class snippets. Bundle formatter when building. Tests compile formatted representative C/C++ and preserve literal contents.
3. Execution: streaming stdout/stderr and line-by-line stdin, EOF, stop, limits. Keep batch input and existing compiler runner. Tests prove output arrives before input and cancellation/flood limits work.
4. Learning: built-in C/C++ exercises with prompt, hint, starter code and multiple input/expected-output cases; run current code against each case; show expected/actual and progress. No solution auto-submission or remote services.
5. Debugging: real GDB MI backend, breakpoints, next/step/continue/stop, source location and locals; input routed to inferior when possible or documented separate console. Tests use real GDB for breakpoint and variable updates. UI disables invalid commands while running.
6. Projects: open folder, file tree, persisted explicit source selection, mixed-language object compilation and linking, include root, save project tabs before build, navigate diagnostics to correct source. Tests build/link a real multi-file project including mixed C/C++.
7. Presentation: light/dark preference, welcome actions and recent files, clear job status. Verify existing editor and example browser tests plus new integration tests.
8. Release: version 2.0.0, updated guide and packaging, build executable and installer when tools available. Smoke test packaged app. Keep previous release intact.

Implementation ledger
- Design choice: reuse GCC/GDB toolchain already available. Use clang-format rather than a partial C++ formatter.
- Existing working directory has user changes; preserve them and implement in place.
- Root owns codelab_studio.py, recovery.py, UI integration and packaging.
- Independent agents own execution streaming, debugger backend, and learning/project/format helpers respectively.

Microsoft Store packaging 2026-09-20 (added after the 2.0.0 release)

  from make_assets.py). Artifact: installer/CodeLabStudio-2.0.0.0-x64.msix, 152 MB
  download / 569 MB installed, 8512 entries, packed with makeappx semantic validation.
- Container fixes in app code: AUMID override now skipped when packaged (it detached the
  window from its own taskbar entry); Help > Compiler Setup no longer tells a Store user to
  copy mingw64 into a read-only WindowsApps folder; the spaced-path tip no longer says
  "move the app"; fix_spaced_compiler_path dropped its C:\CodeLabStudio-compiler fallback

  assignment fails inside the package job, falling back to the existing taskkill cleanup.

  already caught one real bug (a relative toolchain path made GCC resolve cc1 against the

- make_msix.bat gotchas fixed while getting it to run: the file was LF-only, and the SDK
